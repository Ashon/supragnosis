Changes since v0.10.1.

**Upgrade the server and the app, then restart once; an agent's reads follow a merge.**
`brew upgrade`, then `supragnosis restart`. A patch release: the store format, the MCP tools'
inputs, the sync protocol and `status --json` are unchanged.

## Fixes

- **An agent's reads follow a merge.** After one entity was merged into another, `get_entity`
  listed only the surviving entity's own relations and `traverse` walked only its own edges, so
  what the merged-away entity was connected to was gone for agents while the map still drew it.
  Merging `cozodb` (which uses `rocksdb`) into `cozo` left `get_entity` of `cozo` with no relation
  and `traverse` from it with nothing. Both now follow every merged entity's edges, as the map does.
  A search can still name the merged-away entity; reading it forwards to the merged one.
- **A promotion shows at once.** Merging a `claim_promotion` or `claim_demotion` decides which
  spelling and type win, but the stored entity kept the old ones until the next reproject:
  promoting "Postgres" over a later "postgres" left the entity reading "postgres". The entities a
  tier verdict changes are now written with it.
- **A blank search is refused.** `search_knowledge` with an empty or whitespace-only query answered
  the first rows of the store as if they matched. It now says the query is empty.
- **A commit in a git worktree is recorded under its repository.** After a commit, the Claude Code
  hook named the workspace after the worktree's directory, which for an agent's worktree is a
  generated name, so the knowledge from that commit landed in a workspace of its own. It names the
  repository now. Knowledge already recorded under such a name can be copied where it belongs:
  `supragnosis stop`, `supragnosis rekey-workspace --from <that name> --to <repository>`, then
  `supragnosis restart`. The old workspace stays, since the log keeps everything it was given.

## Security

- **tokio 1.53.3** in the server and the app, for RUSTSEC-2026-0386: in 1.53.2 `AsyncFd::new` and
  the constructors beside it violate I/O safety.
