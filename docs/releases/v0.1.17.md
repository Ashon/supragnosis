Changes since v0.1.16.

M3.5 closes here. The proposal gate had a specified set of blocking checks and enforced none of
them, so a merge could commit against entities that were not in the local log - "you cannot promote
what is not there" was written down and not true. They are enforced now, in the fold rather than at
the review call, and writing the property test that was supposed to confirm the enforcement is
order-independent found the defect that makes up this release's one real fix.

The second half of the release is smaller to describe and larger in the diff: the layer that is
supposed to guarantee everything else got its own guarantees. Three of the coverage registry's
promises did not hold when tested, including the one it was built for.

No id-formula or store-schema change, so no migration is needed. The MCP tool surface is unchanged;
`get_proposal` gains `checks` and a `belief_diff` for `entity_merge`, both additive. Upgrade is the
usual `brew upgrade`, then `brew services restart supragnosis-server`.

**One behavior change worth knowing before you upgrade**: a merge verdict on a proposal whose
blocking checks fail now folds to `blocked` instead of `merged`. The verdict stays in the log -
nothing is erased - but it no longer moves the canon. On a node that holds the full log this changes
nothing, because real proposals name real entities. On a node that is still catching up it is the
intended answer, and it becomes `merged` on its own once the missing observations arrive.

## Highlights

### The gate enforces its blocking checks
Section 6 of the proposal workflow specifies them; none existed. Implemented: referential integrity
(the targets are present locally), canonical-target well-formedness for `entity_merge` (an `into`
that is actually among the targets, at least two distinct entities), a stated tier for the gate
kinds, and the T-Box axis collision for `tbox_change` - the one structural check available before a
subtype hierarchy exists, and blocking rather than informative because a structural contradiction is
a bug (Principle 9) while a contradiction between assertions is a fact about the world (Principle 6).

Enforcement lives in the **fold**, not in `review_proposal`, and that placement is the whole design.
A verdict can arrive from another node as a replicated observation and never touch the local review
path, so a gate living there would not be a gate. The fold recomputes rather than trusting a
`check_reported` event: a check result is a cache for the UI, and believing it would let a forged
"pass" promote contamination into canon. `review_proposal` additionally fails fast, so a local caller
gets the reason instead of discovering a blocked state later.

The console shows failing checks above the accept button and disables it - the difference between a
reason and a silent nothing.

### A merge proposal names the references it would rewire
`entity_merge` now carries a computed diff, the last kind with a commit effect to get one. It reports
each edge that moves, what it still connects to afterwards, and whether it **becomes a self-loop**.
That last part is why the diff has to be computed rather than drawn: merging two entities that are
connected to each other turns their edge into a self-loop, `graph()` drops self-loops, and so
accepting silently removes an edge that is on screen at the moment of the decision. Nothing about the
target ids reveals that, which is all the canvas overlay ever had to work with.

It needed no new machinery. `belief_fold` already takes the forwarding map as a parameter, so the
diff is the same fold run twice with one input varied - the "after" side is the code path a merged
verdict takes, and cannot promise an outcome the merge would not deliver. A folded-away target losing
its own belief is filtered out: that IS the proposal, not a consequence a reviewer needs flagged.

## Fixes

- **A blocking check asked the projection, which made canon node-dependent.** Referential integrity
  tested whether a target entity existed as a projected row, making the gate's conclusion a function
  of whether re-materialization had run. A freshly synced node holds every observation while its
  projection is still empty, so the same event set produced two answers: the authoring node said
  `merged`, the receiving node said `blocked`. The check now derives asserted entity ids from the
  log - both entity assertions and relation endpoints, since the projection creates rows for both -
  so it is a function of the event set, as invariant I8 requires. Guarded by
  `i8_blocking_check_conclusion_is_arrival_order_independent`, which delivers one event set whole,
  reversed, and one event at a time, and also pins the direction of change: with the entity
  observation withheld the verdict folds to `blocked` and becomes `merged` once it arrives. The
  reverse would break I16, and nothing can produce it, because entities are never removed.

- **Type definitions with no description were refused on one path and not tested on either.**
  Principle 8's clause with teeth is a refusal, and the only `define_type` call in the whole suite
  passed a valid definition - deleting the validation left every test green. Both entry points are
  now guarded, because a signature proves origin and not well-formedness: a gap between the local
  refusal and the wire refusal is a way for a peer to put a meaningless type into canon that
  `define_type` would have rejected locally.

- **Nine of the ten ways to malform a proposal had no test.** The gate's write surface refuses an
  unknown kind, empty or blank targets, a single-entity merge, a missing or non-member `into`, a gate
  kind with no tier or an unknown one, a promotion of an observation that is not in the local log,
  and a tier on a kind that has no use for one. Each is now checked, along with the message naming
  the fix - the caller is a model with no human beside it - and that no refused proposal reaches the
  permanent log.

## Under the hood

- **The coverage registry is pinned to the document it claims to mirror.** It stated that adding
  Principle 24 would fail the completeness test. It would not: the count was a literal compared
  against the registry in the same file, a tautology that agrees with itself while `principles.md`
  walks away. The document is now embedded and parsed, and each row must carry the document's own
  number and short name, so a renumbered or replaced principle cannot leave a row standing for the
  old one.

- **A declared guard has to run, not merely exist.** The check was that `fn <name>(` appeared
  somewhere - strip the `#[test]` attribute and the guard stops running while the registry keeps
  reporting it as evidence. It now reads the attribute block and distinguishes missing, not-a-test,
  ignored, and running. CI gained `-D warnings` as the second line of defense: workspace lints deny
  `clippy::all`, but `dead_code` is a rustc lint and stayed at warn, which is exactly what an
  un-`#[test]`ed guard becomes.

- **The design documents' own guard claims are swept.** `architecture.md` Section 14 is written in
  "guarded by \<test\>" sentences and the resolution documents carry test-plan tables; five names in
  `resolution.md`'s table pointed at tests that had been renamed, and two rows named no test at all.
  All six documents are now held to the same standard as the registry. A document may name a test
  that does not exist yet only by naming its milestone where a reader can see it - the Status column
  of the row, or the paragraph in running prose - so the exemption lives in the document rather than
  in an allowlist beside it.

- **Evidence is filed per clause, not per principle.** A principle is a conjunction of demands, and
  one verdict per principle hid the demands that are not met behind the ones that are: Principle 2
  read as guarded while its headline clause, "at least one attestation, refused at the schema level",
  was an overdue debt with no test. A fourth evidence state, `Characterized`, is what that split
  required - with only three, a clause pinned by a characterization test had nowhere to go but
  `Scenario`, where it counted as evidence the clause was met, which is the opposite of what such a
  test asserts. The summary now reads **38 guarded of 57 clauses** and prints the seventeen things
  the principles ask for that this system does not do yet.

- **Transaction time is a port.** `aliases_accumulate_and_converge` slept 2ms between ingests so its
  three observations would not share a millisecond - the wall clock the convergence guards are
  otherwise free of, and before the sleep it failed about one run in eight. The sleep also bought
  determinism by steering around the branch where the ordering HLCs tie, leaving the id tiebreak
  untested. `Clock` joins the policy, embedder, event sink and session as an injectable port with the
  node wall clock as its default, and the guard now states both orderings outright, tie included. It
  also names which rule settles the tie: order-independence alone is satisfied by any stable
  iteration order, so the test computes the three content addresses and asserts the lowest-id
  spelling wins.
