# v0.4.0

Changes since v0.3.1.

**Nothing to do on upgrade.** Every existing `supragnosis.toml` keeps working, including the shapes
this release supersedes, and no configuration mistake stops the daemon starting. That is a deliberate
property rather than a happy accident - three of the changes below started life as startup refusals
and were rewritten, because a release that will not come up over a config typo teaches operators to
fear upgrades.

What is new is that a node can now see what its peers actually let it reach, route on it, and show
where each piece of knowledge came from. There is also a two-node sandbox, which is the first way to
watch federation work end to end without two machines.

## A node can see the surface its peers grant it

`/sync/ping` has always answered with the caller's own admitted workspaces - the handler even said
why: a spoke can check connectivity, auth AND authorization in one round trip. Exactly one caller
consumed it, the daemon's health loop, and it read the version and threw the workspace list away.
Then it built its drift view by iterating the spoke's *own* share list, so the view was assembled
from local belief rather than from what the host said.

Worse than unexplained. For a workspace the host does not admit, `advertise` answers `403`, and the
loop discarded that with a bare `continue` - the workspace left the panel entirely, so a
misconfiguration rendered as an absence.

The answer is now kept, per link, and the disagreement is reported in three buckets:

| | |
|---|---|
| **both** | shared here, admitted there |
| **local_only** | this node lists it, the host does not admit it - a setup error |
| **peer_only** | the host would admit it, this node does not share it |

Intersecting the two lists would have hidden the very thing worth seeing. The buckets appear in
`sync_status`, in the viewer's federation panel, and in `/api/federation`, each with the time the
answer arrived. An unreachable host reads as *unknown*, never as an empty grant - a host that is down
must not look like one that revoked everything.

Negotiation happens in the background health loop only. A tool handler reads the cached map under a
lock and never pings, because adding a round trip per host to a call that already blocks would deepen
an invariant this build does not meet (F11).

## Rounds go only to hosts that admit the workspace

`sync_push`, `sync_pull` and federated `search` now narrow to the hosts that admit the workspace, and
every narrowed response carries a `skipped` list. The two halves shipped together on purpose:
filtering without labelling trades a host's loud `403` for an invisible skip.

**A host is dropped only when it said so.** An unanswered host is consulted, because skipping it
would turn "not asked yet" into "not allowed". An empty grant set is different - "admitted, may read
nothing" is an answer - and does narrow.

`supragnosis sync --workspace X` deliberately does not narrow. It names one target, so narrowing
would turn an explicit request into a silent no-op, and the `403` it would have got says more than a
skip.

## One credential per host

`[sync] auth_token` presented a single bearer to every configured server, so each of them held the
credential that also authorizes at the others. Tolerable while a token only fetched knowledge; not
once a host's own answer decides where knowledge goes.

```toml
[[sync.server]]
url = "https://hub-cloud.internal:7420"
auth_token = "..."
```

The flat `servers` + `auth_token` shape keeps working and needs no migration - it resolves to one link
per host with the shared token. Both shapes at once resolves by stated precedence: the per-server
entries win, the flat keys are reported as ignored, and the node starts. Per-server wins because the
other direction would put one flat token on the wire to a host that has its own.

## The graph shows where knowledge came from

The viewer gained a boundary layer with three modes, in the left dock beside the type legends:

- **workspace** - a dashed outline per workspace. The workspace partitions the observed graph, since
  the entity id hashes it, so these outlines cannot overlap. It is also the grain the negotiated
  surface speaks in, so the panel and the graph now say the same thing two ways.
- **origin** - an outline per signing node. These DO overlap, and that is the point: an entity two
  peers both attested sits inside both regions, which no single-owner badge could express.
- **off**

Origin regions key on `origin_node`, the keypair-derived id a signature verifies against, not on the
self-declared `host`. Graph nodes now carry both, as separate fields, because only one of them can be
checked - collapsing them would promote an unverifiable claim into structure.

## A two-node sandbox

```bash
task sandbox:up       # builds the working tree into a hub and a spoke
task sandbox:seed     # knowledge in both, then a sync round per workspace
open http://127.0.0.1:7531
```

The two sides disagree on purpose, so all three buckets appear at once. Seeding then turns them into
outcomes: `shared` pushes and pulls, `spoke-only` is refused with a `403` naming the workspace and the
node, and `hub-only` pulls while pushing nothing - a workspace this node does not share still reads,
because the share list governs what leaves and the host's allowlist governs what may be read.

It is isolated from an installed release by construction: no bind mount into `$HOME`, volumes named
apart from the hub compose file's, its own compose project and image tag, a loopback-bound port block
that leaves 7373 and 7420 alone, and MCP published from neither node.

## Three refusals that became workarounds

Each of these would have broken an upgrade, and none needed to. The pattern was already here and the
first draft did not follow it: a missing embedder proceeds with keyword search, a viewer socket that
will not bind proceeds without the viewer.

| Configuration | v0.4.0 |
|---|---|
| `servers` with no `auth_token` | federation off, node up, reason reported |
| both config shapes at once | per-server wins, flat keys reported as ignored |
| an allowlist entry naming this node | the entry is dropped, the file is left alone |

The last one may happen unasked because admission matches a bearer hash rather than a node id, so
such an entry is a live credential and ignoring it can only share *less*. The filter sits in the
admission directory rather than at a call site, so a runtime reload cannot let it back in. The file
keeps the entry: a mistyped id is still the operator's to correct.

None of them degrades quietly. Every workaround is a note, logged at startup and carried in
`sync_status` as `config_notes`, because a degrade whose only trace was one line at boot has become a
silent one a week later.

What still refuses is unchanged: a non-loopback sync surface without TLS and a non-empty allowlist,
and a store this build cannot read sitting beside an empty one.

## Principle 24, and a chapter for it

The paragraph above is now a principle rather than a habit. `principles.md` gains **Chapter 6 -
Operation**, holding one principle: degrade loudly, refuse only when proceeding is worse. It has its
own chapter because it is not a claim about knowledge - it is an engineering judgment about a process
on someone's machine, and filing it beside the ontology chapters hid that difference.

It arrived through the gate that exists for it: adding a principle fails
`every_principle_declares_its_evidence` until its clauses declare how each is checked, so the four
clauses landed with tests rather than intentions.

## Also

- The federation invariants have an accounting for the first time. `docs/federation.md` Section 8
  declares 21 invariants and none of them was mapped to a guard; adding F21 broke nothing, because
  the completeness check read only the principles document. There is now a registry for both, and the
  shape of the debt was not what "unenforced" suggests - most invariants were held by tests nobody
  had connected to them. 33 clauses, 22 guarded.
- `Deferred` in that registry now covers "holds only incidentally, and nothing checks it" rather than
  only "does not hold". Three clauses had no honest state before, and each carried a hedging reason
  explaining the gap - a definition asking to be fixed rather than worked around.
- The doc-claim scan tightened. Its milestone excuse read a whole paragraph, so a heading saying
  "Repaid by M3b" excused every named test below it, including three that one commit had deleted. It
  now reads the sentence the name sits in.
- Three design documents still described Cozo as the live store, four releases after v0.2.0 removed
  it. P12 is the sharpest case, since the swap is the strongest evidence that principle has - the
  store changed and the knowledge model did not - and it was citing a removed dependency instead.
- The viewer's lint gained `no-undef`, after a new canvas layer reached for a local of `draw()` and
  the graph looked deleted: a render function that throws takes the frame with it.
