Changes since v0.1.19.

Four repairs from a full closure review - the periodic audit that asks whether the principles, the
coverage registry, the deferral ledger and the code still mutually account for each other. Three are
behavior fixes in the engine and sync layer; the fourth is the ledger correcting the one place it
over-claimed. Every repair lands with its guard registered in the coverage registry, which now reads
68 clauses: 43 guarded, 2 structural, 2 pinned-but-unmet, 21 unmet-and-unpinned. That is one owed
clause MORE than before, on purpose: an over-claiming row was split into what its tests actually
evidence and what is honestly still owed.

No id-formula or store-schema change, so no migration is needed. No tool was added or removed.
Upgrade is the usual `brew upgrade`, then `brew services restart supragnosis-server`.

**Three behavior changes worth knowing before you upgrade.**

- A workspace re-key (and a legacy-id migration) now carries a synced claim's tier as the
  receiver's evaluation - capped at `host_signed` - instead of verbatim.
- After a re-key, all-workspaces reads show BOTH rows: the source workspace's original is no
  longer hidden from the unscoped view.
- A proposal's `proposer` and `opened_at` now name the authoring attestation, so a proposal row
  that absorbed attestations from elsewhere may display a different (correct) author and an
  earlier (correct) opening time than before.

## Highlights

### Dropping a sync stamp is no longer a tier promotion

The receiver-evaluated tier has one trusting branch: a stamp-less attestation's claim is taken at
face value, because the only thing that wrote stamp-less rows was the local observe door, and that
door forces the default tier. Two operator paths quietly broke the premise. `rekey-workspace` and
`migrate` both re-create rows under a new content id, and both must drop the sync stamp - it signs
the old id and cannot follow - but both carried the claimed tier verbatim. So a peer-asserted
`human_confirmed`, correctly evaluating `host_signed` while stamped, evaluated `human_confirmed`
after one CLI act, and from there won belief selection outright. A tier promotion is supposed to be
a gated verdict under a surface ceiling; this was one flag away from `supragnosis rekey-workspace`.

Both paths now clamp the carried claim to its pre-strip evaluation, so a claim evaluates after the
re-key exactly as it evaluated before it. The premise, as stated in resolution.md and on
`evaluated_tier` itself, now names every stamp-less producer that holds the line - which is the
actual fix, since the old wording ("no sync stamp = authored by this engine") was an invariant
nobody was checking. Guarded on both paths by a scenario test whose fixture uses a hostile claim,
not the default tier the old guard happened to use.

One thing this release cannot do is repair the past: the log is append-only, so a row re-keyed
before v0.1.20 keeps the claim it carried. If one exists and matters, cap it the gated way - a
`claim_demotion` through the proposal gate.

### The unscoped view is the union of the scoped ones

The live-set door folds a re-keyed predecessor out of every read, so that one act does not count as
two. It recognized a predecessor by lineage plus byte-identical content and assertions - but not
workspace. For `migrate` (same workspace, new id formula) that is exactly right. For a workspace
re-key it meant the SOURCE row vanished from every `workspace=*` read while the source workspace's
own scoped view still showed it: two reads of one log disagreeing, and the all-workspaces graph
showing a workspace's entities without the support its own view reports.

The door now supersedes only within one workspace. A migrated pair still folds to one row; a
re-keyed pair stays live on both sides, each workspace keeps its own support, and the unscoped view
is what it should have been all along - the union of the scoped ones.

### One rule for who authored an act

An observation's provenance is a set that grows by union, and after an absorb it is sorted for
determinism. Three folds needed "the authoring attestation" off such a row, and they did not agree:
the verdict-surface fold and reprojection used the earliest effective HLC, while the proposal fold
used `first()` - which names whichever host sorts first - for the proposer, and `max(observed_at)` -
which moves forward every time an attestation lands - for the opening time. The rule is now one
helper, `authoring_attestation`, shared by all three, and the proposal view names the author and
the authoring time regardless of what absorbed onto the row afterwards.

### The ledger stops over-claiming P17

The registry's P17 row said "the local read surface is reachable only by the local principal" and
cited three guards - the viewer's socket-directory test, the sync bind guard, the origin check.
None of them touches the MCP streamable-http daemon, which serves the full tool surface - writes
and `sync_push` included - on loopback TCP with no auth layer. Loopback confines a port to the
host, not to a single user: on a multi-user host, any local account reaches it. That daemon was the
one surface where the self-accounting was wrong rather than honestly deferred.

This release fixes the accounting, not yet the daemon. The clause now claims exactly what its tests
evidence (the viewer socket and the sync bind); the daemon carries its own deferred row, owed at M4
remainder, to be repaid the way the viewer was - a unix-socket transport or an auth layer; and
architecture.md and federation.md now say one thing about F19's hard line instead of two. Until
that lands, the daemon's confinement is what it always actually was: the host boundary, plus a
rebinding guard. Single-user hosts are unaffected; on a shared host, prefer stdio or stop the
daemon.

## Under the hood

- The two re-key scenario tests introduced in v0.1.19 (`p2_a_workspace_rekey_carries_provenance...`,
  `p23_a_rekey_does_not_carry_proposal_events...`) are now registered in the coverage registry, so
  renaming, deleting or un-`#[test]`ing one reports its clause as unguarded instead of silently
  losing the guard.
- Four new scenario guards ride the fixes: the tier clamp (both paths, hostile-claim fixture), the
  unscoped-view union, and proposal attribution under absorbed provenance.
