Changes since v0.5.0.

**Upgrade, restart, fetch the model once; the daemon embeds what it already holds.** `brew upgrade`,
`supragnosis restart`, and `supragnosis embed fetch` if this node does not have the model yet. No
`reproject` is needed: the running daemon finds the model and embeds the knowledge written before it,
and `supragnosis status` shows how far it got. The store, the sync protocol, the MCP tools and the
prompts are unchanged. Coming from v0.4.x, read the [v0.5.0 note](v0.5.0.md) first: it ended Intel
Mac support and set the Linux floor at glibc 2.39.

## The daemon embeds what was written before the model

v0.5.0 brought semantic retrieval but left an existing node two steps after the upgrade: fetch the
model, then `reproject` with the daemon stopped - once per workspace, which its note did not say.
Even then only entities got vectors. An observation's vector is attached when the observation is
written, and `reproject` rebuilds the graph, not the log, so everything a node had observed before
the model stayed findable by keyword only, for good, without a word about it.

Now the daemon does it. Once the model's files are in `~/.supragnosis/models` it embeds, once, every
observation and every entity, in every workspace, that has no vector. It checks for the files every
30 seconds, so a fetch made while the daemon runs is picked up without a restart; the same covers a
new install, whose daemon starts before `service install` has fetched the model. While it runs,
`status` reads `semantic on (...) - embedding what was written before the model: 40 of 120`; if an
embed fails it stops and `status` says why, and the next start tries again. On a copy of the
author's store it embedded 178 observations in under six seconds.

It writes vectors and nothing else: no observation row, no attestation and no owed-projection entry
changes, and a vector already stored is never replaced. An entity that a new observation renames
while the backfill is embedding it keeps no vector for its old name; the next start embeds the new
one. Vectors stay node-local and never travel in a sync.

On a node that has knowledge without vectors, the backfill loads the model when it starts, so the
daemon holds its full memory (about 1 GB) from then rather than from the first search.
`SUPRAGNOSIS_EMBED=none` still keeps a node keyword only and small.
