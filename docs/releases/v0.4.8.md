Changes since v0.4.7.

**Upgrade, then restart the daemon once; a spoke that sets `insecure_tls` names its hub's
certificate first.** `insecure_tls` is no longer read, and every sync link now verifies its hub. A
spoke that reached a self-signed hub through it should copy the hub's `tls_cert` and name it with
`ca = "<pem file>"` in that hub's `[[sync.server]]` entry before upgrading, or its rounds fail until
it does. A `http://` URL to another machine now disables the link. Nodes on either side of this
release still sync with each other. A store is recorded at format 2, which v0.4.4 to v0.4.7 still
open.

## Sync: nothing lost, counted twice, or let through

The 2026-10 adversarial review's federation findings, re-traced against v0.4.7: ten defects, every
one still present. Each fix has a test that failed on the code before it.
([docs/sync-correctness.md](https://github.com/Ashon/supragnosis/blob/main/docs/sync-correctness.md))

- **A stamp carries when it was observed, not when it was exported.** An edit observed at t=100 and
  exported after a peer's t=500 edit used to become the newer one, everywhere.
- **One act is stamped once.** Two rounds at once - two MCP sessions, or a hub answering two pulls -
  could stamp one observation twice, and both stamps were kept.
- **A seq is issued once.** The counter now lives beside the node key (`node.seq`), so a store
  restored from an older backup no longer reissues seqs its peers already hold - events that were
  then never delivered.
- **A rejected event holds its stream instead of leaving a hole.** Accepting event k+1 after
  rejecting k used to skip k for good. Now k is offered again until it is accepted. An event this
  release cannot decode is rejected alone, where it used to fail its whole batch every round.
- **A signature has one spelling.** Uppercase and `+`-prefixed hex verified too, and each spelling
  was kept as another attestation. A configured key in another spelling is named and ignored.
- **A peer pushes only for origins granted the workspace.** A hub used to accept, from a peer
  granted workspace A, signed events of an origin it admits only to B.
- **A query stays home unless its workspace is shared.** Remote search used to send the query text
  for any workspace.
- **The bearer goes only to a verified host, encrypted.** See the first paragraph. A named
  certificate is trusted as itself, so one `openssl req -x509` made with its defaults works - the
  same for a remote MCP profile's `ca`.
- **Every request is bounded.** A push goes in batches and a pull in pages, under declared size
  limits and 60 s timeouts. A surplus past 2 MB used to be refused whole, every round. `observe`
  refuses content past 1 MiB, so every event fits.
- **Both sides say which protocol and release is talking.** A hub records each peer's, and when it
  refuses to serve a workspace because a node has not consented, it names that node's release, or
  says the release is not known - a release before v0.4.5 cannot send consent at all.

**Mixed releases.** A newer spoke and an older hub, or the reverse, keep syncing: the new headers
and fields are ignored by an older peer. An older client pulling from this hub receives at most one
page of 500 events per round, so a large backlog takes a few rounds to arrive.

## A store records its format

Nothing in a store said which release wrote it. An older binary opening a newer store dropped rows
it could not parse and stripped fields it did not know when it rewrote them.
([docs/compatibility.md](https://github.com/Ashon/supragnosis/blob/main/docs/compatibility.md))

- **The first open records the store's format** (2) and the lowest format that may share it (2).
  v0.4.4 to v0.4.7 ignore the record and open the store as before.
- **A store a later release changed past this one is refused, unchanged,** naming the release that
  changed it.
- **A store last written by v0.4.3 or earlier is upgraded, and the store as it was is kept beside
  it** as `knowledge.redb.format-1`.
- **Every encoding that crosses versions is pinned.** A store the released v0.4.7 wrote is read back
  whole by every build: every content id recomputed, every signature re-verified.

## Contracts other programs read

- **The MCP server names itself.** Clients were told it was `rmcp 3.5.0`; it now says `supragnosis`
  and its version.
- **The tool list is pinned** - names, descriptions and input schemas - so a change to what an agent
  learned reaches review as a diff.
- **`status`, `connect` and `server --json` carry `"schema": 1`.** The CLI and the app's readers are
  tested against the same example documents, and the app says to update itself if a newer CLI
  raises the schema.

## The release pipeline

- **The desktop app is built with a pinned tauri CLI,** installed in a step that holds no secrets.
  The signing secrets reach only the build step.
- **Every action is pinned to a commit,** and Dependabot waits a week before proposing a new
  version.
- **No cargo cache is restored into what is published.** The workflows are linted for these rules
  (zizmor) on every change.
- **macOS and the desktop app are checked on every pull request,** and `task check` runs what CI
  runs.
