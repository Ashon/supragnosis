Changes since v0.4.9.

**Upgrade, then restart the daemon once; the recall gate holds, and a brief cites what it reads.**
`brew upgrade` then `supragnosis restart`. The store, the sync protocol and every client
configuration are unchanged. Two tool descriptions changed and two tool answers gained fields; no
input schema moved, and the prompt list is the same.

## A recall merge counts only from the human console

A `recall` proposal - the bulk retraction of everything derived from a contaminated source - is
the verdict with the largest destructive radius, and the principles make its verdict a human's
direct act that no agent may cast on anyone's behalf. The tool description said so. The code did
not: a merge verdict on a recall cast through the MCP `review` tool was accepted and folded to
`merged`. Harmless today, because recall has no commit effect yet - and a trap for the day it
gets one, when every agent-cast merge already sitting in a log would fire at once.

The fold now counts a merge on a recall only when the verdict carries the engine-stamped console
marker, and demotes any other to a comment - whichever path it arrived by, replicated or cast
before this release. The agent surface refuses to cast one and says where to decide; a comment
is still accepted. The rule lives in the fold rather than at the write path because a replicated
verdict never passes through the write path, and because a merge that reached the log earlier
must not fire later. The principal-signed act that replaces marker trust under multi-principal
federation stays owed, and the ledger says so.

## A brief cites what it reads

The `brief` prompt tells the model to cite every claim and gave it, for a theme, only member
names - nothing `get_entity` takes. A theme is now named by its hyperedge id (the content address
of the member set) and lists its members as name and entity id. `workspace_map` gains the same
two fields beside the names it already showed, and its truncation note points at `get_entity` by
id. A query result carries the path to where its answer came from; that is Principle 2, and a
name alone did not keep it.

## A hub admitting principals alone starts

A hub with TLS, admitted principals and no allowlisted node, listening off loopback, died at
startup: the daemon pre-validated the bind with the allowlist count alone, while the server
counts allowlisted nodes and principals together. The daemon passes the same sum now.

## Also

- The design principles were reviewed as a logical system and the document revised where it
  disagreed with itself or with a later document: the T-Box act is the gate (P11 with P23), a
  recall verdict is a principal-signed act and an elicitation response is a claim unless signed
  (P23 with P18, as F20 already demanded), a generated summary is never stored (P7, as
  consolidation.md had read it), and open-world answers are an enumerated alphabet with one rule
  for refuse-or-unknown (P5). Appendix A names five tensions that were resolved elsewhere and
  says which of its judgments rest on mechanisms still owed. The preamble states what the
  document governs and what it does not, and that every revision declares whether it tightens,
  loosens, reinterprets or corrects a fact.
  ([docs/principles.md](https://github.com/Ashon/supragnosis/blob/main/docs/principles.md))
- excision.md E10: excision outranks finality. A decision whose record is excised is un-decided
  and its effects fall with it; the closure names those decisions before the act. Specified
  before anything is built, so the first implementation inherits the rule.
- The coverage registry now accounts for every design document's invariant table, not only the
  principles and federation: 16 families, 269 clauses, each with an evidence state and each owed
  one naming its repayment. An invariant written into a document without a state fails the
  build, and the registry found the hub bind bug above and several stale sentences while the rows
  were mapped. A new case pins that each prompt's digest is the same bytes twice over one store.
