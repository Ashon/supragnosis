Changes since v0.1.18.

Two fixes on the MCP surface that share a shape: the daemon held the answer and did not say it. Neither
was a data defect - nothing was lost or miscomputed in either case. What went wrong is that a correct
response was phrased so that the only conclusion available to the reader was the wrong one. A survey of
an empty workspace reported an empty node; an aged-out session reported an authorization failure. In
both the server knew better and had no way to say so.

Both were found the same way, by an agent reading this server's own answers and drawing exactly the
wrong conclusion from each. That is the useful test for a surface whose readers are mostly programs:
not whether a response is true, but whether being wrong about it is easy.

No id-formula or store-schema change, so no migration is needed. No tool was added or removed. Upgrade
is the usual `brew upgrade`, then `brew services restart supragnosis-server`.

**One behavior change worth knowing before you upgrade.** A request carrying an unknown
`Mcp-Session-Id` now answers `404 Not Found` where it used to answer `401 Unauthorized`. This is what
the MCP Streamable HTTP spec asks for and what clients already handle, but a client that special-cased
the old 401 will see the status change.

## Highlights

### An empty workspace survey says where the knowledge is

`workspace_map` scopes to the node default workspace when no workspace is given. Knowledge is
deliberately organized into named workspaces - one per project - so that default is an addressing
default and is routinely empty. The survey reported `node_count: 0` and advised widening to `'*'`,
which is correct and useless: a reader who does not already know the workspace names has no next move,
and the reading actually available is "this node holds no knowledge".

The store this was found against holds 141 entities across 31 co-occurrence clusters, all of them in
the workspace `supragnosis`, with the node default empty. The survey of that node said nothing is
there. `search_knowledge` spans all workspaces unless narrowed, so it kept returning hits the whole
time, and the contradiction between the two made the empty answer read as a fault rather than a scope.

`Engine::workspaces()` already computed the list of workspaces holding knowledge and simply was not
reachable from the MCP surface. It is surfaced on the empty path now: the response carries
`knowledge_in_workspaces` naming them, beside a note that frames the miss as scope rather than absence.
Structured, not only prose - a machine reader should not have to parse a sentence to recover. A
genuinely empty node keeps separate wording so the two cases do not blur, and a failed enumeration
degrades to the plain note rather than failing the survey.

No new tool for this (Principle 21). A `list_workspaces` would widen the surface to answer a question
that only arises at one moment, in one response, which is where the answer now is. The server
instructions and the `workspace` argument docs also state the model outright, and `observe`'s argument
warns that omitting the workspace splits a body of knowledge across two, leaving every later scoped
read showing half of it.

### An expired session answers 404, so clients reconnect themselves

MCP Streamable HTTP gives 404 a specific meaning: a 404 to a request carrying `Mcp-Session-Id` tells
the client to start a new session, and clients re-initialize on it. rmcp answers an unknown session
with `401 Unauthorized: Session not found`, which is a different signal - a client reads 401 as an auth
failure. Claude Code takes it for an OAuth challenge, requests OAuth discovery, and surfaces the parse
error from the empty-bodied 404 that comes back, never reconnecting.

The cost is paid on every daemon restart. The session a client established is gone, nothing in the
exchange says it merely aged out, and every connected client is stranded until each is reconnected by
hand. The failure is also unusually good at hiding: `claude mcp list` reports the server connected,
because a fresh handshake works, while every tool call from the existing session fails with an error
about OAuth that has nothing to do with the cause.

The daemon translates that one response on the way out. Only that one - rmcp emits a second 401,
`Session ID is required`, for a request that carried no session id at all, which is malformed rather
than expired and which re-initializing would not fix, so it keeps its status. Deciding on a body string
is the whole risk here, so the classification is a separate function under test: the two rmcp wordings,
an unrelated 401, a non-401 carrying the same words, and a non-UTF-8 body. Responses that are not 401
return untouched and unbuffered, which leaves the SSE streams alone, and a body that cannot be read
keeps its original status rather than inventing an expiry.

## Under the hood

- **The landing page stopped clipping its own code.** The two-column terminals overflowed by 114-145px
  at 1440px, so the `observe` example lost `"to": "CozoDB"` - the conclusion of the relation it was
  demonstrating - and the MCP section truncated the one line a visitor comes to copy. `overflow-x` was
  auto so nothing was unreachable, but overlay scrollbars leave no hint there is anything to reach for.
  The samples are reflowed to fit the column they live in, and the panes carry a visible scrollbar at
  the widths where they still cannot.

- **No JS no longer meant no page.** Every section below the hero started at `opacity: 0` waiting for an
  IntersectionObserver with no fallback, so a blocked or broken script left 90% of the page blank. The
  hidden state is gated on a class set in the head, and the observer setup reveals everything if it
  throws. Alongside: `--faint` carried real content at 3.12:1, under the 4.5:1 AA floor, and it is the
  colour of the code comments holding most of the explanation in the pipeline section - now 4.93:1. A
  trailing `.section-note.wide` overlapped the cards above it by 10px and is keyed on position now, the
  hero constellation's labels no longer land on the headline, and shared links have a preview card.
