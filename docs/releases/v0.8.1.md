Changes since v0.8.0.

**Upgrade the server and the app, then restart once; the search index rebuilds in one click.**
`brew upgrade`, then `supragnosis restart`. The server and the app changed. The store's format, the
sync protocol and the MCP tools are unchanged. `status --json` gains `embedder_conflict` and keeps
its schema number.

## The search index rebuilds in one click

A store records the search model of the first process that opens it with one, and refuses every
other, since vectors from two models share no space. A person reported a daemon that would not
start, its log saying:

> store was written with embedder 'hashing-256' but was opened with
> 'paraphrase-multilingual-minilm-l12-v2-q-384'

Their store had been opened once with `SUPRAGNOSIS_EMBED=hashing`, a development stand-in. Once is
enough, and from then on every start under the default model was refused, launchd started the
daemon again and again, and only the log said why. The refusal asked for a re-embed that no
command did, and the app showed the daemon as not running, with a Restart that failed the same way.

- **In the app**, Settings > This Mac says why such a daemon cannot start - "The search index
  needs rebuilding", with both models - and holds **Rebuild index** where Restart was. One click
  stops the daemon, removes the index and starts the daemon again, which embeds every observation
  and entity with the model it runs; the Search row shows it, "Indexing - 152 of 437" with a bar.
  Rebuild index is also on the Search row whenever the daemon runs with a model, for anyone who
  wants the index made again. Setup's server step names it too.
- **`supragnosis embed rebuild`** does the same from a terminal, for a daemon this CLI manages: a
  login job this home installed, or one `supragnosis start` runs. It refuses anything else - a
  Homebrew service, an AI app's stdio server, a `serve` in a terminal - with nothing changed.
  `supragnosis embed reset` is its first half, for a daemon run by hand and stopped first.
- **The refusal and `status` say how to go on.** Both name the model that wrote the store, the
  one the daemon runs, the rebuild, and `SUPRAGNOSIS_EMBED=none`, which runs without semantic
  search and leaves the store as it is.

Rebuilding changes nothing but the index: the log and the graph are as they were, and the index is
made again from the log. It is not on a timer, since rebuilt with the same model an index comes
out as it was.

If your daemon is down with that error, open Settings > This Mac and click Rebuild index, or run
`supragnosis embed rebuild`. If you started it with `supragnosis service install --env
SUPRAGNOSIS_EMBED=none` to get it running, give the job its model back first with `supragnosis
service install --env SUPRAGNOSIS_EMBED=fastembed`. Then remove `SUPRAGNOSIS_EMBED=hashing` from
wherever it was set - a shell profile, a `.env`, a hand-written plist - or the next process that
reads it pins the store again.
