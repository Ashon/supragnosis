Changes since v0.1.11.

A desktop-app bugfix release. The knowledge model and the MCP tool surface are unchanged; the
viewer UI embedded in the server binary gets one cosmetic change (the header mark), so the
usual upgrade reminder applies: `brew upgrade`, then `brew services restart supragnosis-server`.

## Highlights

### Reopening the app brings the viewer back
Closing the viewer window drops the shell to the menu bar (tray-only), and relaunching the app
from Finder/Spotlight/Launchpad does not start a new process - macOS delivers a reopen event to
the running instance, which the shell ignored. So "opening the app again" showed nothing, and
the tray's Open Viewer was the only way back. The shell now handles reopen and shows the viewer
window, per the macOS convention.

### Traffic lights sit centered on macOS 26
macOS 26 gates window-control metrics on the SDK an app was linked against: the previous
releases were built on a macos-14 runner, got the compatibility traffic-light metrics, and
landed the lights off-center in the overlay title bar. The release app build is now pinned to
an SDK-26 runner, which restores the calibrated centering (and keeps it on macOS 15, where the
metrics are unchanged).

## Everything else

- The viewer header's mark is now the app icon's 5-spoke asterisk (an inline SVG, identical
  geometry to the favicon) instead of a "*" text glyph, so the mark renders the same on every
  platform. Header geometry is unchanged.
