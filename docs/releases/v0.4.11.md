Changes since v0.4.10.

**Upgrade, then restart the daemon once; a search finds the words you type, in any order.**
`brew upgrade` then `supragnosis restart`. The store, the sync protocol, the tool list and every
client configuration are unchanged. The `brief` digest gained a section.

## A keyword search finds every term, in any order

Release builds ship without an embedder, so the keyword match is the recall surface most nodes
have, and it matched the whole query as one substring. Against a live store, `pg-boss` found
fifteen rows and `pg-boss 부팅 크래시` found none - beside an entity named `pg-boss default import
부팅 크래시`. What someone types is the right words, rarely in the order the knowledge wrote them.

A text now matches when it holds the whole query (a phrase match) or every whitespace-separated
term of it, in any order and anywhere (an all-terms match). A phrase ranks above an all-terms match
of its kind, entities above observations. The rule only widens - a phrase holds each of its own
terms - so nothing that matched before stops matching, and a one-word query behaves as before.

- **Every term is required.** Matching any one term would answer `pg-boss crash` with every row
  that says `crash`; partial matching is what the semantic surface is for.
- **An entity is matched one spelling at a time** - its name, then each alias - so two names never
  combine into a match neither holds.
- **No morphology.** A term matches as a substring (`crash` finds `crashes`), but an inflected form
  the text does not contain - a Korean particle glued to a noun - is not found.
- **A miss says how to retry.** A keyword search with no hits now tells the caller every term must
  appear, so a model tries fewer terms instead of concluding the knowledge is absent.

The rule is one function in `supragnosis-core` that both stores call, held by a conformance case,
and the recall eval gained a keyword-only measure: five reordered or gapped queries recalled
nothing under the old rule and all five now.
([architecture.md Section 4.2](https://github.com/Ashon/supragnosis/blob/main/docs/architecture.md))

## A brief separates what was learned from what was decided

Running v0.4.9's `brief` against a live store, "what arrived last" was fifteen rows of
`proposal(open) entity_merge: [hex ids]` and `proposal(merge) <id>` - the replay of a batch of
merges, each labelled `agent_extracted` - and nothing the agents had learned. A proposal event is
stored as an observation, but its text is machine shorthand and its tier is the writer's, so among
knowledge rows it read as a claim.

The digest now has two sections. `recent_observations` holds knowledge only.
`recent_proposal_events` holds opens, verdicts, comments and withdrawals, each with the proposal's
kind and current state, its targets by name, and whether a verdict came from the console or an
agent. The model is told to report the two apart and never to report a decision as knowledge.
