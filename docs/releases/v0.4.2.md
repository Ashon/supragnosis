Changes since v0.4.1.

**Upgrade if you run a hub or sync to one.** rustls moves to 0.23.45 for RUSTSEC-2026-0285: earlier
releases accept TLS 1.3 handshake messages across encryption level boundaries, and the sync API is
the one surface that binds beyond loopback, behind exactly that TLS stack. A standalone node never
opens it.

**Then restart the daemon.** Everything else here is in the viewer, and the viewer is served by the
daemon - its pages are compiled into the server binary - so a new desktop app in front of an old
daemon shows the old viewer. `brew services restart supragnosis-server` (or `supragnosis restart`)
is what makes this release visible. The store, the MCP surface and the sync protocol are unchanged.

## The inspector stops repeating what the whole scope agrees on

The node inspector printed every field it received on every node. Measured on a real store at the
desktop shell's default window size, that spent the panel on what never varied - one effective tier
and one origin host across all 336 entities, and a "belief decision" disclosure whose every field
had a single candidate - while its height cap cut the busiest node to 6 of 17 relations and 2 of 10
evidence rows.

Leaving things out is the repair, and it is the one with principle stakes, so it was specified
before any code moved, in
[docs/inspector.md](https://github.com/Ashon/supragnosis/blob/main/docs/inspector.md). A field is
now silent when the whole loaded scope holds one value for it, and the panel says so once - `same
across this scope: agent_extracted / from localhost` - because a row that is usually there and is
not reads as "no tier" (P5). Uniform rather than majority: a majority rule makes silence a statistic
that flips as unrelated nodes arrive. The consequence is worth knowing in advance: confirm one
belief by hand and the tier varies across the scope, so every node shows its tier again. That is the
rule working.

Contested beliefs are outside all of it. A tie on trust is shown expanded with its actions in every
scope; only a conflict trust already resolved folds, to a line that still says it exists. The
busiest node's header goes from five lines to three, and the panel shows 8 of 17 relations and 3 of
10 evidence rows.

## Text is set for reading

The viewer named a serif it never shipped - no `@font-face`, and the CSP names no `font-src` - so
its prose always fell through, and for Hangul it fell through to the system Myungjo face, which
blurs at 12-13px on a dark ground. What a person reads (descriptions, evidence, names) is now the
system sans; identifiers (relation kinds, ids, hashes, counts) stay mono, so they still read as
identifiers. Bundling a face was weighed and not taken: about 2MB in every binary, for a face that
is what the system font already looks like on macOS, where the shell runs.

Two rendering defaults were also unset. Light text on near-black is now drawn with grayscale
antialiasing instead of macOS's stem dilation, which read as bold and soft at 1x. And Korean wraps
at the spaces its writer put, not between any two syllables: `word-break: keep-all`, with
`overflow-wrap: anywhere` so a long unspaced identifier still cannot overflow a column. One cost,
measured in WebKit and accepted: keep-all also opens a break after the period of a dotted
identifier.

## A label's halo cannot drift off its text

Graph labels drew a background-colored `strokeText` as a halo and then `fillText` at the same point,
and the halo sat visibly off the text. Measured in the shell's engine on a 1x display: `fillText`
snaps glyphs to the device pixel grid, `strokeText` draws the outline at the exact fractional
coordinate, and node positions are always fractional - so the two parted by up to 0.26px
horizontally and 0.15-0.5px vertically, by a different amount every frame as the layout moved.
Snapping the anchor does not close it, because the vertical residual differs by glyph.

So the halo is no longer a second rendering. Each label is baked once into a sprite: the same glyphs
drawn in the background color at whole-pixel offsets inside a disc, then the name on top. Every copy
is the identical raster, so registration holds by construction, and the sprite is blitted on whole
device pixels. A translucent label now fades as one unit, so hull names no longer show their own
halo through their glyphs, and a frame does one image copy per label instead of two text layouts.

## Also

- `chacha20` 0.10.1 was yanked upstream, and `deny.toml` refuses yanked crates, so the cargo-deny
  gate had been red on main since the v0.4.1 release commit itself. The lockfile moves to 0.10.2.
  The rustls advisory above was published after that run, which is why no run had reported it.
