Changes since v0.4.11.

**Upgrade, then restart the daemon once; a console merge raises an agent-merged promotion.**
`brew upgrade` then `supragnosis restart`. The store, the sync protocol, the prompt list and every
client configuration are unchanged. One tool argument's description changed wording; no tool or
argument moved.

## A console merge after an agent's raises the promotion

A promotion proposal's tier ceiling comes from the surface its merge verdict was cast from: an
agent's merge grants at most `host_signed`, and a merge from the human console grants up to
`human_confirmed`. A person who confirmed in the console a promotion an agent had already merged got
nothing for it. The two verdicts carry the same content, so they are one observation with two
attestations, and the fold read only the first attestation's marker, the agent's.

The ceiling is now the highest among every attestation of every merge verdict on the proposal, so a
further verdict can raise a grant and never lower it. The recall rule had the same blind spot and
gets the same fix: a console act on a recall merge an agent's attestation reached first now counts.
Both are read from the log at query time, so a store that already holds such a pair shows the
higher tier after the restart, and nothing is rewritten. The `brief` prompt's proposal events name
the console as a verdict's surface whenever one of its attestations came from there.

## The design documents, the principles and the code say the same thing

Every design document was read against `docs/principles.md` and against the code, one statement at
a time. Where a design document had decided something the principles never recorded, the
principles took the decision as a declared revision instead of the document backing out. Each one
is named on the principles' 2026-10 revision line:

- **P23**: a demotion or a recall may be approved by its own proposer, as a correction (I9).
  Excision is the one act outside the gate and outranks finality. A valid merge outranks any later
  verdict, and finality is reached at causal stability, as federation.md already held.
- **P2**: an observation requires host, workspace and time; an unstated source or confidence is
  preserved, as the schema has done since M0.
- **P24**: an unknown configuration key is the third refusal shape, which the config parser
  already enforced, and a non-loopback bind counts admitted principals beside nodes.
- **P17**: a remote `*` read is answered from the caller's grants. Only the local trust surface,
  the stdio server included, queries node-wide.
- **Vocabulary**: "recall" now means only the retraction. Fetching knowledge is "retrieval", in
  the documents, the comments and the text agents read. Code identifiers keep their names.

A new registry test fails the build when a cross-document reference points at a section or an
invariant that does not exist.

## Also

- The bind refusal and the MCP loopback refusal state the current rule. A non-loopback sync
  listener needs TLS and an admitted node or principal, and remote access goes through a hub's TLS
  listener, which serves sync, and MCP for admitted principals.
- Homebrew: on arm64 Linux, `brew install supragnosis-server` installs the aarch64 tarball. It used
  to install the x86_64 one, which cannot run there. The stable cask names its conflict with the
  dev cask, so installing one over the other says why it stops.
- The systemd guide installs from the release's Linux tarball, which has shipped for aarch64 since
  v0.1.21, and keeps building from source as the fallback.
- Dependencies: futures-util 0.3.34, flate2 1.1.10; eslint for the viewer's lint.
