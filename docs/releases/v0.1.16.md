Changes since v0.1.15.

The release where the guarantees stopped being assertions. `architecture.md` Section 14 claims
"guarded by <test>" in seven places, and until now CI ran no Rust test at all - every one of those
guards held only while a human remembered to run it locally. One of them had been failing about one
run in eight, unnoticed. That is fixed, and with it a set of defects the fix made findable.

No id-formula or store-schema change, so no migration is needed. The MCP tool surface is unchanged;
the viewer API gains fields and one endpoint, all additive. Upgrade is the usual `brew upgrade`, then
`brew services restart supragnosis-server`.

## Highlights

### Duplicate concepts get caught without an embedder
An entity id is `blake3(workspace + trim+lowercase(name))`, so case and whitespace variants already
collapse at write time - which also means the `duplicates` curation signal, keyed on that same
normalization, can never fire within a workspace. The conservative merge band would catch the rest,
but it needs an embedder, and the prebuilt binary ships without one. On such a node the net dedup
signal was: nothing beyond case. `TrustTier` versus `Trust Tier` had no detector at all.

The **name-variant ladder** is that detector. It groups by a key stronger than the id key - separators
and punctuation dropped, then a naive plural fold, then alias crossing - and reports a group at the
first rung that forms it, carrying the same shared-neighbour corroboration the band reports. It needs
no embedder, so it works on every node.

It generates candidates and commits nothing. Folding these variants into the id would change every
existing id, and would silently merge pairs that must stay distinct: `TrustTier` the Rust enum and
`Trust Tier` the design concept differ by one separator and are two concepts. Naming the variance is
the substrate's job; deciding identity remains the gate's.

### A proposal now carries a computed diff
"No merge without a diff" was honoured by UI convention: the viewer drew a canvas overlay from the
proposal's target ids, and an agent opening a proposal over MCP got nothing. The diff was the one
review artifact the gate could not produce.

`get_proposal` now computes it for `claim_promotion` / `claim_demotion` - the kinds that have a commit
effect. It reports which observations' effective tier moves and which beliefs that overturns, carrying
`contested_before`/`contested_after`, so contradictions settled or created fall out of the same
comparison. A contradiction still does not block a merge; it just stops being invisible.

It needed no new machinery: merge forwarding is a read-time overlay and the belief fold already takes
the forwarding map and gate grants as parameters, so the diff is the same fold run twice with one
grant added. The "after" side is computed by the code path a merged verdict would take, and cannot
promise an outcome the merge would not deliver.

The curation console shows it as before -> after rows on the selected proposal, so accepting is a
decision about a visible delta.

### Empty no longer means two different things
`merge_suggestions: []` meant "no near-name pairs", "no embedder here", or "ran over part of the
workspace" - only the first is a negation, and a reviewer reading "0 suggestions" off a node with no
embedder concludes there are no duplicates from a signal that never looked. The report now carries
`merge_band` (`available` / `embedded` / `examined`), the same refusal to conflate absence with
unavailability that makes `search_knowledge` label its recall mode. The counts matter: configuring an
embedder after knowledge already exists leaves older rows without vectors, and that under-covered run
would otherwise look exhaustive.

The same distinction applies to the new diff - three proposal kinds still enforce nothing, and their
diff says `computable: false` with the reason rather than returning an empty one.

### Viewer
- `/` focuses the search field from anywhere, and the field advertises the shortcut with a key badge
  that clears itself on focus. Escape hands the keyboard back to the canvas.
- Minimap nodes get the same background-colour halo the graph nodes have. Without it, adjacent dots
  of one type fused - a dense cluster rendered as a single blob, which defeats the one thing a
  minimap is for.

## Fixes

- **Cross-adapter `traverse` divergence.** A relation endpoint with no projected entity row made the
  two store adapters answer the same log differently: Cozo's final rule inner-joins `*entity` and
  dropped it, while the in-memory adapter emitted a hit whose name was the empty string. Both now drop
  it and both still traverse *through* it, matching what `graph()` and `curation()` already do with an
  edge whose endpoint falls outside the node set. This was an overdue M4 entry condition, and sync's
  partial-ingest state is what would have made it reachable.
- **A workspace sentinel is not a place to write.** The read endpoints resolve `*`/`all` to "every
  workspace"; all four write endpoints forwarded it raw, so acting from the all-workspaces view filed
  observations into a workspace literally called `*`. Candidate generators had the mirror bug, offering
  merges for pairs spanning two workspaces - a merge with nowhere coherent to be filed.
- **A false rationale in the log.** Sharing the merge band's row markup meant a ladder candidate was
  recorded as "merge-band suggestion (embedding-near names)" on a node with no embedder. A proposal is
  an immutable observation, so its stated evidence has to be true; the source is now a whitelisted
  parameter rather than client free text.
- **Candidates already awaiting a verdict** are no longer re-offered, so a reviewer cannot file
  duplicate proposals for one merge.

## Under the hood

- **CI runs clippy and the test suite** (`.github/workflows/rust.yml`). It mirrors `task check`, minus
  the ESLint half `frontend-lint.yml` already owns.
- **A flaky guard was a wrong guard.** `aliases_accumulate_and_converge` demanded that two arrival
  orders produce the same representative spelling, which a recency policy does not promise: the two
  builds are different logs, and P16 promises convergence over the same observation set. It passed only
  when all three observations shared a millisecond and fell through to the id tiebreak - testing the
  tiebreak whenever it passed and the policy whenever it failed. Split into the two claims that are
  true.
- **Principle coverage is an executable registry.** Every principle declares how it is checked -
  scenario, structural, or deferred - and the declaration is itself tested: a renamed test reports its
  principle as unguarded, and a new principle fails the completeness check until someone picks a state.
  Currently 18 scenario / 2 structural / 3 deferred, of 23.
- **Policy cases test the change, not the final state.** Most principles here constrain a difference -
  nothing may be forgotten, a generator may not commit, a proposal may not move the canon before its
  verdict - and a test that only inspects the end state cannot tell "the rule held" from "the rule was
  never exercised". Cases snapshot before and after and assert a named clause about the delta.
- **The ledger's own gaps are closed.** The document header claimed v0.1.5 and "M3 has not started"
  while Section 12 recorded M3a and M3b as shipped; Section 13 listed an open decision Section 14
  recorded as repaid; Principle 10 was the only principle with no compliance entry; and the tombstone
  deferral named no repayment milestone despite already describing its own due date. All reconciled.
- **A `Taskfile.yml`** wraps the dev loop and the gate. `task dev` runs your build on its own
  db/socket/port, `task dev:snapshot` runs it on a copy of the live daemon's knowledge, and `task
  check` runs exactly what CI runs.
