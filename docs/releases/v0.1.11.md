Changes since v0.1.10.

A packaging release: the Homebrew surface gets its final token layout and a correct upgrade
path. The server binary, the MCP tool surface, and the desktop app are functionally identical
to v0.1.10.

## Highlights

### Homebrew tokens: `supragnosis` is the app, `supragnosis-server` is the daemon
`brew install supragnosis` now resolves to the desktop-app cask - it owns the plain token and
pulls the server formula via depends_on. The server/CLI formula is `supragnosis-server`; the
installed binary is still named `supragnosis` either way. If you installed under the old
tokens (formula `supragnosis`, cask `supragnosis-app`), stop the service before reinstalling -
the tap README has the exact commands.

### The upgrade path actually works now
Two fixes, verified against Homebrew's own sources (6.0.12) and a live upgrade run:

- The cask carries `uninstall quit:`, so an upgrade quits the tray-resident app before
  swapping the bundle and reopens it after. Previously the old instance kept running from a
  deleted bundle and served the stale UI.
- `brew upgrade` does not restart a running service - without a restart the old daemon keeps
  running from the deleted keg (and the viewer UI is embedded in the daemon binary, so the app
  shows the old release). The upgrade procedure is:

  ```sh
  brew upgrade
  brew services restart supragnosis-server
  ```

  The formula caveats print the same reminder.
