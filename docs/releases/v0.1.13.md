Changes since v0.1.12.

The resolution-layer release. M3's belief and identity halves land: the "current belief" is no
longer last-write-wins by luck but a deliberate, replaceable, trust-weighted policy; conflicting
beliefs surface for human mediation instead of resolving silently; and the substrate now proposes
entity merges and accumulates aliases instead of leaving resolution to the operator. The viewer
gains a minimap and a clearer conflict-mediation UI, and a developer dev channel arrives for both
the server (`brew install --HEAD`) and the desktop app (`supragnosis-dev` cask).

The knowledge model changes are additive - no id-formula or store-schema break, so no migration is
needed. Upgrade is the usual `brew upgrade`, then `brew services restart supragnosis-server`.

## Highlights

### Belief resolution (M3a): the current belief is a chosen policy, and conflicts surface
The projection was last-write-wins by replay order - a default that was never chosen. It is now a
replaceable `TierWeighted` policy (highest effective trust tier, then latest HLC, then id;
confidence is carried but never selects). The tier that resolution and display consume is the
receiver's own evaluation - a synced claim can never evaluate above `host_signed`, so a peer's
self-declared tier cannot raise your graph's trust. When distinct values tie on trust, the belief
is **contested**: the viewer rings the node and lists the competing values, and one console
confirmation settles it through the gate. `claim_promotion` / `claim_demotion` verdicts now
commit (they set the tier the policy consumes), and only the human console can grant
`human_confirmed` - an agent-cast verdict caps at `host_signed`.

### Identity resolution (M3b): aliases, a merge band, and a unified write path
- **Aliases accumulate.** Distinct asserted spellings of one entity are kept as aliases (the
  representative is the policy's pick), searchable on both store backends, and a merged-away id
  keeps forwarding to its canonical entity.
- **A conservative merge band.** Entities whose names are semantically near (embedding similarity)
  surface as `merge_suggestions` in the curation console - the substrate proposes, and "propose"
  opens an `entity_merge` through the gate for review. Nothing merges automatically.
- **One resolution write path.** `observe` and `reproject` now run the same fold, so an incremental
  write produces exactly the row a fresh replay would - the old drift between the two is gone, and
  the entity embedding is recomputed only when its name/alias text actually changed.
- **T-Box conflicts surface too.** Contested type definitions read exactly like a contested entity
  kind (one mediation UI), and a name defined on both the entity and relation axes is flagged.

Deferred with explicit ledger notes: inducing (and naming) new types belongs with the extraction
port (M5); bitemporal time-travel queries are M3c.

### Hyperedge management
Co-occurrence hyperedges now resolve membership through accepted merges (so the graph and
hypergraph agree), and a recurring context can be **reified** - asserted as a group entity plus
`member_of` relations through the normal ingest, carrying the lineage of every co-asserting
observation. A hyperedge stays a derived view; only the asserted grouping becomes first-class.

### Viewer: minimap, quieter chrome, clearer mediation
A minimap (whole-graph overview with a draggable viewport) docks beside the zoom controls;
fit-to-view now uses the full window width so a narrow window no longer shrinks the graph;
workspace selection lives only in the left-rail chips (the header text input is gone); and the
contested-value box replaces two identical "confirm" buttons with a clear "keep" (lock in the
current value) versus "use this" (switch to a competitor).

### Developer dev channel
- **Server/CLI**: `brew install --HEAD supragnosis-server` builds current `main` from source
  (refresh with `brew upgrade --fetch-HEAD`). The viewer UI is embedded in the server binary, so a
  stable desktop app renders a HEAD server's viewer.
- **Desktop app**: `brew install --cask supragnosis-dev` installs a rolling, signed/notarized
  build republished from `main` whenever the shell changes (refresh with `brew reinstall`).

## Everything else

- Desktop app: a spawned daemon that dies immediately is detected and its failure shown on the
  splash (instead of an eternal "starting..."), and the app prefers the Homebrew binary over a
  stale one on `~/.local/bin` (a Finder-launched app does not inherit the shell PATH).
- The Homebrew README is now in English.
