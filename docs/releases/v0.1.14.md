Changes since v0.1.13.

The observability release. The log is the source of truth and the graph is a projection of it
(Principle 1), yet the viewer only ever showed the projection. This release lets you see the log
itself: browse the raw observation events, and, for any node, read the observations behind its
belief and why each field resolved the way it did.

The changes are additive - two new read-only viewer endpoints and their view structs, no id-formula
or store-schema break - so no migration is needed. Upgrade is the usual `brew upgrade`, then
`brew services restart supragnosis-server`.

## Highlights

### The observation log is browsable (Log tab)
A Log tab joins the right dock beside Proposals / Review / Types / Peers: the workspace observation
log, newest-first, each event carrying its provenance (who, on-behalf-of, when, claimed and
receiver-evaluated tier) and effective tier. Because a proposal and its verdicts are observations
too (Principle 23), the log shows them alongside knowledge events - the "log is the truth" model
made visible. A row expands to its provenance and the entities it asserted (click one to focus it).

### Why a node is projected this way (log column + belief decision)
The node inspector gains a "log" column beside outgoing / incoming: the observations that back this
node's belief, each expandable to its provenance. A "belief decision" disclosure explains the
resolution of each single-valued field (canonical name, kind) - the winning value plus the
non-winning ones tagged alias or competitor, each with its effective tier and asserting observation.
It is folded from the same policy the graph uses and is built on the entity view, so the explanation
always agrees with what the graph shows (a new invariant test pins "explanation == projection").

### A confirmed belief reads as settled
Once a contested belief is human-confirmed there is nothing higher to promote it to, so the inspector
stops offering the confirm buttons and shows a committed "confirmed" chip with settled wording,
instead of leaving a lingering confirm dialog on an already-decided belief.

## Everything else

- New MCP-less viewer endpoints back these surfaces: `/api/observations` (the log; `entity=<id>`
  narrows to one node's evidence, `limit` caps it) and `/api/explain?entity=<id>` (a node's per-field
  belief decision). Both are read-only projections - a storage failure is an error, never an empty
  result (Principle 5).
- fix: the node inspector no longer keeps a stale contested ring or state after a belief changes.
  Graph-node fields that serde omits when false or empty (contested, competitors, aliases, ...) were
  persisting across polls on the reused layout object; they are reset before the fresh node merges in.
- fix: the right dock no longer overlaps the minimap - its height cap now reserves for the minimap
  (the tallest element in the bottom-right corner) rather than only the zoom HUD.
- The install one-liner now fetches from https://supragnosis.dev/install.sh (the docs site) instead
  of the raw GitHub URL. scripts/install.sh stays the single source - the pages workflow copies it
  into the published site - so the README, the site, and the script itself now show the same command.
