How it works

Follow one fact from a note to an answer.

Most agent memory cannot answer three questions about what it holds. Here is how supragnosis answers each one.

  • Who said this? step 1
  • Has anyone checked it? step 3
  • Does my other machine know? step 5

1 / 5 write

Agents write as they work.

While they code, debug and decide, your agents call observe with a note and whatever structure they have. After a commit, Claude Code is asked for the decision behind it, so the why is kept without anyone asking. Each entry keeps its workspace, which machine wrote it, for whom, from what source and how sure. Entries are never edited, only superseded.

entry 1 append-only

workspacepayments-api hostlaptop foryou sourcegit:4f2a9c1 confidence0.9

Answers: who said this?

2 / 5 structure

The log becomes a graph.

A deterministic projector turns entries into entities and relations, and what is said together gathers into a region. Delete the graph, replay the log, and the same graph comes back on any machine.

3 / 5 govern

Disagreements wait for you.

When agents give one thing two different types, both stay and the conflict waits for you; nothing in the log is overwritten. Changes to what counts as true, like merging two names for one thing or confirming a claim, arrive as proposals you accept or reject on the Review page. Your verdict goes into the log like any entry, and Review can reverse it. Once merged, an agent asking about either name reads the one thing.

4 / 5 recall

Any agent can ask, and gets receipts.

Weeks later a different agent searches. Hits come back ranked, and reading one gives the entries behind it: which machine wrote them, for whom, when, and how far they are trusted.

5 / 5 travel

Your other machine gets the same memory.

A second machine joins a hub with a one-time code: supragnosis invite on the hub, supragnosis join on the machine, and three words to compare. Then the log syncs on its own, one workspace at a time, and is never flattened into merged state. Each machine checks every signature and replays the same graph, verdicts from Review included. An entry that only claims a person checked it counts for no more than its signature proves.

Check it yourself in a minute.

With supragnosis and jq installed, paste this into a terminal. It runs a server on a store held in memory, so none of the entries is stored, and sends it three entries: two that give retry-policy different types, and one that carries AWS's published example access key.

{ printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"check","version":"1"}}}' \
  '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"observe","arguments":{"workspace":"check","content":"retry-policy is a pattern","entities":[{"name":"retry-policy","type":"Pattern"}]}}}' \
  '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"observe","arguments":{"workspace":"check","content":"retry-policy is a setting","entities":[{"name":"retry-policy","type":"Config"}]}}}' \
  '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"observe","arguments":{"workspace":"check","content":"deploy key AKIAIOSFODNN7EXAMPLE"}}}'
  sleep 1
  printf '%s\n' '{"jsonrpc":"2.0","id":5,"method":"resources/read","params":{"uri":"supragnosis://workspace/check/graph"}}'
} | supragnosis serve --store mem --embed none 2>/dev/null | jq -r '
  if .id == 4 then .result.content[0].text | fromjson | .error | split(". ")[0]
  elif .id == 5 then .result.contents[0].text | fromjson | .nodes[]
    | "\(.name): \([.type] + [.competitors[].value] | sort | join(" or ")), contested: \(.contested)"
  else empty end'

It prints:

refusing to store this: the content contains something shaped like a credential (aws-access-key-id, at byte 11)
retry-policy: Config or Pattern, contested: true

Both types stay side by side until you pick one in Review, and the key never reaches the log, which is append-only and could not give it back.

Works with the tools you already use.

Claude Code, Claude Desktop, Cursor, VS Code, Codex, Gemini CLI and OpenCode connect with one command and no token to copy, or with Connect in the app's Settings.

supragnosis connect claude-code
# or claude-desktop, cursor, vscode, codex, gemini, opencode

With Claude Code, connect also adds a hook: after a commit the agent made, the agent is asked for the decision behind the change, and each session starts knowing what the project's workspace holds. The hook itself writes nothing.

Where it honestly stands.

Shipped

  • Keyword and semantic search
  • Type conflicts flagged, not hidden
  • Proposals and the Review page
  • Signed sync through a hub, joined with a one-time code
  • The commit hook for Claude Code
  • Verdicts reversible from Review
  • MCP prompts: brief, curate and two more
  • The desktop app, Homebrew and an install script

Owed, not scheduled

  • Questions about time: "true until last month"
  • Verdicts signed by the person who cast them
  • Tracing and recalling a bad source
  • Forgetting and consolidation

Not for you yet if

  • you need Windows or an Intel Mac
  • several people cast verdicts on one hub
  • a Mac should sync with a hub on your local network, which macOS keeps its daemon from reaching

The roadmap keeps a record of what shipped and what is deferred, in architecture.md sections 12 and 14, and every principle, clause by clause, says which of its demands a test holds.

Questions

Does anything leave my machine?
Only what you share. Sync is off until this machine joins a hub, and then it carries only the workspaces you allow.
Do I need an API key or a model?
No. Search uses a local embedding model fetched once (224 MB); until then, keyword search works and says so.
What if I stop using it?
Your knowledge is a directory, and its log replays into the same graph on any node.
How is this different from a notes file?
A notes file keeps what someone wrote. This keeps which machine and person said each thing and whether it was confirmed in Review, and shares it with every agent and machine you use.

Up and running in a few minutes.

  1. Install

    # the desktop app, signed and notarized, with the server
brew install --cask ashon/tap/supragnosis && open -a Supragnosis

# or the server alone, running at every login
brew install ashon/tap/supragnosis-server
supragnosis service install
    # x86_64 or arm64, glibc 2.39+, checksum-verified
curl -fsSL https://supragnosis.dev/install.sh | sh

# keep it running, connect your AI apps, fetch the model
supragnosis setup
    git clone https://github.com/Ashon/supragnosis
cd supragnosis
# fastembed = the local embedding model, as the release is built
cargo build -p supragnosis-cli --features fastembed

  2. Set up

    The app's Setup keeps the server running at login, offers to connect each AI app it finds and downloads the search model in the background. On Linux or a server, supragnosis setup does the same.

  3. Try it

    Ask your agent to remember one decision and why. Setup says when it is in, and the Graph shows it.

The daemon serves MCP on 127.0.0.1:7373 and the viewer on a unix socket. The embedding model (224 MB) is fetched once by Setup, service install or supragnosis embed fetch; until then search is keyword only, and supragnosis status says so.
