Principles

How a shared memory stays honest.

Twenty-four principles decide what supragnosis keeps, believes, shares and refuses. Each one is split into clauses, and each clause names the tests or the construction that hold it, or says that it is owed, which means the code does not yet guarantee it.

Chapter 1 Epistemology

What is kept

Claims rather than facts: who said them, when, and what is believed because of them.

P1

Assertions, not facts.

The log keeps what was said, by whom and when. What is believed is computed from it, and computing it again gives the same graph.

Two machines can disagree, and either can be wrong. Keeping the claims and deriving the belief means a better rule can read the same log again.

5 clauses: 4 tested, 1 by construction
  • the graph is a projection: re-deriving it from the log reproduces it exactlytested by 4 named tests
  • a generator proposes; nothing but a verdict commitstested by 1 named test
  • a read is answered from the log as it stands, not from a stale view of ittested by 4 named tests
  • ingest validates well-formedness and nothing beyond ittested by 1 named test
  • no API may write a fact that did not pass through an assertion directly into the graphholds by construction

P2

Every claim has an author.

Each entry carries the machine, the person it acted for, the workspace and the time. A confidence nobody stated stays unstated.

An agent usually works on someone's behalf. Without the chain, nobody can tell a guess from a decision, or trace a bad one back.

5 clauses: 5 tested

  • a query result can carry its provenance: a hit dereferences to its observation, with its attestations and delegation chaintested by 1 named test
  • a relayed attestation is authenticated by its origin's signature, not by the relaytested by 2 named tests

P3

Correct, never erase.

A correction supersedes an entry and the old one stays readable. The same entry arriving twice changes nothing.

Deleting loses the reason something was believed. Superseding keeps that history for whoever needs it later.

  • a re-materialization concurrent with an observe cannot interleaveowed

P4

Two clocks.

When something was true and when the system learned it are recorded apart.

Knowledge goes stale on both axes. A fact learned late is not a fact that became true late.

2 clauses: 1 tested, 1 owed

P5

Missing is not false.

A search that finds nothing says 'not found', never 'no'. Each kind of non-answer keeps its own name.

Every node holds part of the picture. Reading a gap as a no turns missing knowledge into a wrong answer.

5 clauses: 4 tested, 1 owed

P6

Disagreement is information.

When sources conflict and trust cannot settle it, the answer says 'contested' and keeps both sides.

A silent winner hides the one place a person should look.

3 clauses: 2 tested, 1 owed

P7

Forget by ranking, not by deleting.

Old knowledge should fall in retrieval, never out of the log. Consolidation suggests and commits nothing.

Attention is finite and the log is not. Forgetting is how attention gets spent.

Chapter 2 Ontology

How it is shaped

A vocabulary that starts small, grows from use and stays consistent.

P8

One name, one meaning.

A type enters the vocabulary only with a plain-language definition, and a description once written is never erased by an omission.

Agents from different tools read the same vocabulary. A name with two meanings splits the graph without anyone noticing.

3 clauses: 2 tested, 1 owed
  • a type cannot enter the vocabulary without a natural-language definitiontested by 1 named test
  • a description already captured, an entity's or a relation's, is never erased by a later omission, and a blank description is an omissiontested by 1 named test
  • a relation type reads its direction from its name, and relates_to is the one catch-all, treated as not yet classifiedowed

A vocabulary that cannot contradict itself.

Two definitions of one type surface as contested, and a name defined twice blocks the change that would add it.

The data may disagree. The vocabulary that reads the data may not.

Extend, don't modify.

Your vocabulary grows in the log. The core model stays fixed, and a change to it comes with a migration.

Every workspace names its own things. None of them should need a new build to do it.

P11

Let the schema emerge.

Notes come in untyped. Names said together form a context, and promoting one writes an entry that names its lineage.

Nobody designs a good taxonomy up front. A schema induced from use fits the work it came from.

P12

Not tied to a store.

The model is defined above any encoding. The store is an adapter, and it has already been replaced once.

Storage formats change faster than meaning. Knowledge should survive a change of database.

What it is, and what it does.

'Person' is a kind and 'reviewer' is a role held for a time. Roles should be relations, not subtypes.

A role that becomes a subtype cannot end. The person stops reviewing; they do not stop being a person.

Chapter 3 Identity and trust

Who said it, who sees it

Stable names, one graph from one log, and trust that the receiver decides.

P14

Names that do not move.

Identifiers come from content, so the same entry has the same id on every machine, and an id still resolves after a merge.

An id that depends on where something is stored breaks the moment it travels.

Same thing, two names: the system's job.

Each tool speaks its own vocabulary. Asking every client to agree first would mean they never connect.

P18

Every write could be wrong.

A sender's claim of trust is kept as sent and evaluated by the receiver. A signature proves who sent it, not that it is true.

Poisoning an agent's memory is an attack. The defense is trust that the receiver computes, never trust the sender declares.

Chapter 4 System

How it is built

Code decides and models help. A small surface, and nothing extra to maintain.

P19

Deterministic core, probabilistic edge.

Models widen search and draft proposals. What commits is decided by code that gives the same answer every time.

A model can be swapped, can be missing and can be wrong. The graph cannot depend on any of that.

Chapter 5 Governance

What becomes canon

Writing is free. Trust is granted by a verdict.

P23

A gate to the canon.

Anything can be written. Only a verdict on a proposal changes what is trusted, and proposing alone changes nothing.

Free writing and careful promotion pull apart. Putting the gate on promotion only keeps both.

Chapter 6 Operation

When parts fail

Keep serving, say what is off, and refuse only when serving would mislead.

P24

Degrade loudly.

When a part cannot start, the rest keeps serving and says what is off. It refuses only when going on would be worse.

A server that will not start over a typo teaches people to fear upgrades, and a server nobody upgrades stops getting fixed.

  • two conflicting settings resolve by a stated precedence that names what it ignoredtested by 1 named test

Tensions

When two principles pull apart.

Principles collide. Each collision has a ruling. Where the mechanism behind a ruling is not built yet, the cautious side holds: nothing is removed, demoted or merged automatically.

  1. Ingest first, and leave a path to refine. Knowledge that never came in cannot be refined either.

  2. Do not block ingest. Suspicious knowledge comes in and is held at the lowest tier: a label, not a locked door. owed The mechanism behind this ruling, the quarantine tier, is not built yet, so the cautious side holds.

  3. Privacy wins. A demand to destroy is the one exception to Principle 3, and it leaves a tombstone. owed The mechanism behind this ruling, the tombstone, is not built yet, so the cautious side holds.

  4. Not a conflict. The log is kept forever and retrieval is finite. Forgetting spends attention, not storage. owed The mechanism behind this ruling, retrieval demotion, is not built yet, so the cautious side holds.

  5. Caution is the default. Merge automatically only in the confident band; when unsure, propose a candidate. owed The mechanism behind this ruling, the auto-merge band, is not built yet, so the cautious side holds.

  6. Small is the default. Compose the existing tools first, and promote a pattern only when it repeats. owed The mechanism behind this ruling, a check that the surface stays one tool per recurring intent, is not built yet, so the cautious side holds.

  7. Models only widen retrieval. What commits stays deterministic.

  8. Degrade loudly. Refuse only when going on would serve a wrong answer, an unauthorized surface or a configuration other than the one written.

  9. The gate is on promotion, never on writing. Even with review backlogged, knowledge exists and circulates at a low tier.

  10. Most of it is automatic. Only new contradictions, high-impact or structural changes and recalls reach a person. owed The mechanism behind this ruling, the checks that route review, is not built yet, so the cautious side holds.

  11. The gate is the act. A merged type change defines the type; defining one directly is the shortcut for working alone. owed The mechanism behind this ruling, the gate for type changes, is not built yet, so the cautious side holds.

  12. Destruction wins. It does not pass through the gate, and a decision resting on what was destroyed is undone with its effects. You see which decisions fall before you act. owed The mechanism behind this ruling, excision, is not built yet, so the cautious side holds.

  13. Both hold. A split is a new proposal; the merge stays in the log and only its forwarding is removed.

  14. Outside your grants, an id is unknown rather than refused. A refusal is only for a scope you named.

  15. The channel carries the question and the signature carries the answer. A reply alone grants nothing above the agent's ceiling. owed The mechanism behind this ruling, asking a person through elicitation, is not built yet, so the cautious side holds.

  16. Not a conflict. Evaluation depends on the entry alone and the policy is in the log, so one log gives one canon. owed The mechanism behind this ruling, evaluating a replicated verdict marker against the canon policy, is not built yet, so the cautious side holds.

Method

How a principle is held.

A principle is a conjunction, so it is checked clause by clause. Every clause declares one of four states, and the build fails when a clause declares none, or when a test it names stops running.

Tested by name
Named tests show the clause holds. Rename or delete one and the clause reports itself unguarded.
Holds by construction
The code cannot express the violation, like a crate graph with no path from the core to storage. The mechanism is written down.
Owed, behavior pinned
The clause does not hold yet. A running test records today's behavior, so repaying it means rewriting that test.
Owed
Not assured: it may not hold, or it holds with nothing checking it. It names the milestone that repays it, or the event that brings it due.

Rules about change are tested as change.

Most principles forbid a difference: nothing may be forgotten, a proposal may not move the canon. A final state cannot show that, so these cases snapshot the store before and after an act and check the difference.
