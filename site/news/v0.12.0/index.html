supragnosis v0.12.0

Upgrade, then restart once; the app and the viewer speak Korean, and an agent opens a record.

Changes since v0.11.0.

Upgrade the server and the app, then restart once; the app and the viewer speak Korean, and an agent can open a record it found. brew upgrade, then supragnosis restart. The store format and the sync protocol are unchanged, so a 0.11 node and a 0.12 node still sync, and nothing needs a reproject. Two answers of the MCP tools changed in a way a script could notice; they open the next section.

Read before upgrading

  • On macOS 14 Homebrew asks for up-to-date Command Line Tools. GitHub stopped running the macos-14 runner on 2026-11-06, so the Homebrew bottle is built on macOS 15 and pours on macOS 15 or later (arm64_sequoia). On macOS 14 the formula installs the same prebuilt binary without a bottle, which Homebrew does only with an up-to-date Xcode or Command Line Tools, though nothing is compiled; releases through 0.11.0 poured there. The app is unchanged in what it runs on.
  • search_knowledge refuses a scope it does not know. Any word but local, remote or both was read as local, so a call that passed one searched this node without saying so. It now answers an error that names the three.
  • The sync tools with no workspace act on what the node shares. sync_pull, sync_push and sync_status used to fall back to the node's default workspace, which a node whose workspaces are named after projects never wrote. With no workspace named, a pull takes every workspace the node shares or receives, a push every shared one, and each answers {workspaces: [...]}, one entry a workspace; sync_status answers version_vectors, a map by workspace, in place of workspace and version_vector. A named workspace answers as before. A remote search with no workspace asks no host and says to name one.
  • resources/list lists supragnosis://workspaces alone. It also listed the default workspace's graph, hypergraph and types; the templates still read those for any workspace by name.
  • Building from source needs Rust 1.90, down from 1.96 (see "A smaller build").

The app and the viewer in Korean

The app, its menu bar and tray, Setup, Settings and the viewer - the map, the Log, Review, notices and the sheet - show Korean when macOS gives the app Korean, and English otherwise (i18n.md). The site has had its Korean pages since November; the Korean landing now names the app's pages as the app does.

  • The app follows macOS. It reads the language macOS picks for it - your preferred languages, or the one set for this app under System Settings > General > Language & Region > Applications - and has no language setting of its own. The viewer opened in a browser follows the browser.
  • What stays as written. A record's content, an entity's name, a type and a workspace's name are shown as they were written. What agents read - the MCP instructions, tool descriptions, prompts and the hook's text - stays English, as does the command line.
  • Still English inside Korean pages: a refusal's reason and a check's detail, which the server writes for one case, and the names of the engine's checks in Review.
  • supragnosis setup --events carries a code and its values beside each say, so the app words a step in its own language instead of parsing the sentence.

An agent can open what it found

v0.11.0 gave each session its project's newest records. A look at what an agent could do next found that a search hit shows a record's first 160 characters and the whole record opened only as an MCP resource, which a client may not give its agent: a subagent surveyed on 2026-11-28 had no resource tool at all.

  • get_entity opens a record. Given an observation hit's id, or an index line's link, it answers the record in full, as the resource does. The usage log counts it as an opened record.
  • search_knowledge says how to search: two or three topic words, the project's workspace, then without one before concluding nothing is recorded, and how to open a hit. A record's hit carries its workspace and the day it was recorded.
  • A record opens with its finding. observe and the question after a commit ask for the finding in the first sentence, since the index and a hit show only the start.
  • Smaller: get_proposal and review take the id as proposal_id, the name propose answers it under; the index says its days are UTC; a refusal no longer cites a principle or a document an agent cannot read; a store failure and a missing sync setup name the command that helps (supragnosis status, supragnosis invite and join); supragnosis --help lists each command on one line.

Two spellings of one type are one type

On the author's node 138 of the 139 items under Needs you were contested types, and 30 of those differed only in case or separators: Component and component, Session and session. A person asked to choose between two spellings is asked nothing about what is true.

  • An entity's type is compared by the fold a relation's type already takes, so two spellings do not contest each other and are not listed as a conflict. The spelling the policy picks is the one shown, and every spelling stays in the log (resolution.md Section 4.1).
  • Types that differ in meaning - Component and Feature - contest as before. On the same store 108 remain.
  • Nothing stored changes, so there is nothing to rebuild.

The site

  • The news list orders releases of one day by version, newest first; a release's tab reads "v0.12.0 - supragnosis news".
  • The landing shows the Linux install tab first only on desktop Linux, not on a phone or Windows.
  • The Privacy pages carry a share preview. Korean copy was tightened in several places, and Review's queue is "확인할 항목" wherever it is named.

A smaller build

The viewer's page, styles and scripts are served as they are written. The three build-time minifiers are gone: measured on an Apple silicon Mac, one clean release build each, the lock file went from 502 packages to 376, a build of the CLI compiles 239 packages instead of 390 and took 46 s instead of 56 s, and the binary grew by 277 KB. The advisory exception the CSS minifier needed is removed, and the lowest Rust that builds the workspace is 1.90.

Smaller changes

  • Dependencies. rmcp 3.11.0, url 2.5.9 and cookie 0.18.3 close five RustSec advisories.
  • Docs. architecture.md, i18n.md and the principle registry say what is built as of this release; two functions and one branch left by what 0.11.0 removed are deleted.
