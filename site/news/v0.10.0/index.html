supragnosis v0.10.0

Upgrade the server and the app, then restart once; a second machine joins with a code.

Changes since v0.9.0.

Upgrade the server and the app, then restart once; a second machine joins with a code, and the daemon syncs on its own. brew upgrade, then supragnosis restart. The store moves to format 4, which v0.9.0 still opens: min_reader stays 2. The first open re-projects every workspace once, before the daemon serves - about two seconds a workspace at today's sizes. The sync protocol and status --json are unchanged; MCP answers gain fields and lose none.

Read before upgrading

  • A node with a hub syncs by itself. It pushes and then pulls every five minutes, and once soon after it starts; a failed round waits longer, up to an hour, and sync_status says when the last round ran, what it moved and why the last one failed. Before, a round ran only when a tool or supragnosis sync asked. The rounds cover the same workspaces the tools did.
  • A write waits out a re-materialization. reproject now holds the engine's write lock, so an observe that lands while one runs waits for it instead of being overwritten by it. That race was real: the observe was lost from the graph with nothing owed until the next re-projection. The vectors a reproject needs are computed before it takes the lock, so the wait is the projection's, not the model's.
  • A person's no holds through a tie. A merge you rejected from the console stays out of Suggestions until something is said about one of its entities in a later millisecond. An observation made in the same millisecond as the reject could lift it once that node stamped its log, so a pair could come back at sync time with nothing new said.

A second machine joins with a code

On the hub, supragnosis invite makes the TLS certificate and the listener if there are none, and prints a one-time code that expires in ten minutes. On the other machine, supragnosis join reads the code, checks the hub's certificate against it, and shows three words; the hub's terminal shows the same three, and Allow there answers with a signed, sealed reply the joining machine verifies before writing anything. The joined machine receives the workspaces you ticked and sends only what you chose. supragnosis peer list and peer remove keep the hub's list, and supragnosis hub leave undoes a join. A Linux server can be the hub, invited over SSH.

On a Mac, macOS's Local Network privacy keeps the daemon a login job runs from reaching a hub on the local network. Such a node keeps working offline: it records as before, its rounds back off, and sync_status and the round say why, naming Local Network access. The Settings sheets for inviting and joining wait for a route around it.

The daemon gains an admin socket that only its owner can reach: supragnosis sync runs a round through the running daemon, and the invitation commands talk to it. A sync listener that cannot open - an unreadable certificate, an address it may not bind - no longer stops the daemon; it says why and the rest of the node serves.

Review and the map

  • Demote this claim on an observation's card lowers it to Unverified, says first what the change moves - the value, the ring, the relations, the ceiling and the checks - and has an Undo.
  • Suggestions say what they held back. "By meaning" counts the near pairs the band left out, and "By name" the alike names the ladder left out, because they wait, were rejected by you, or were pulled apart. An empty list now says which.
  • The window's pages get exactly the app permissions they use and nothing beyond them.

Settings says what happened

  • A Start at Login change, a Use or a Remove that the CLI refuses now shows as a failure with the CLI's reason, and stays until it is read. Before, it showed as a success with the refusal beneath it, and dismissed itself.
  • A refusal that quotes the credential you pasted reaches the page with the credential replaced. A server add the CLI refuses before reading the credential answers with that refusal, not a broken pipe.

For agents

  • supragnosis://entity/{id} and supragnosis://proposal/{id} read an entity and a proposal by id, as get_entity and get_proposal answer them; an id outside your grants reads as unknown.
  • Graph edges carry sources, the number of attestations asserting them, summed over the rows a merge collapses. A second assertion of an edge now adds to its support instead of replacing it; how far the edge is trusted is computed as before.
  • curate reports merge_band.held_back and name_ladder.held_back.

Under the hood

The coverage registry's owed clauses went from 134 at v0.9.0 to 104, each now held by a test or by construction, and writing those tests found the defects above. Among the new guards: a store that fails is reported as failing on every sync call, a projection write that fails leaves its debt for the next open, and the first test that runs the CLI binary, with PATH holding only a scripted launchctl, so the machine's own daemon is never touched.
