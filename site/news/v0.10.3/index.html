supragnosis v0.10.3

Upgrade the server and the app, then restart once; start says started only once it is.

Changes since v0.10.2.

Upgrade the server and the app, then restart once; start says started only once it is. brew upgrade, then supragnosis restart. A patch release: the store format, the MCP tools' inputs, the sync protocol and status --json are unchanged.

Fixes

  • supragnosis start says started only once its daemon answers. It printed "daemon started" before the daemon existed and exited 0 whatever the daemon then did. A daemon that refused its configuration - a --http address that is not loopback, a store another process holds, a config file that does not parse - left only its log, and the next command found nothing running. start now waits after it forks. It says started once the MCP address answers. When the daemon exits first, start exits 1 with the error the daemon logged and the path of its log. After thirty seconds of neither, it says the daemon is still starting. restart of a daemon that start began waits the same way. A daemon run by launchd or systemd (supragnosis service install, the app) is unaffected: install already waited.
  • join and hub leave finish when they restart a daemon start began. They restart the daemon so it picks up the new hub, and with a daemon start began, that restart ended the command as the new daemon forked: the summary, and the JSON line of --json, never printed. They print now, after start's own lines.
